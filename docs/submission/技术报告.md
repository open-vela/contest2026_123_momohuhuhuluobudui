## 2、摘要

AgentGuard 是运行于 ESP32-S3-EYE 和 openvela/NuttX 的桌面健康与隐私守护终端。系统使用 ESP-DL 在设备本地检测并框选人脸，依据人数和持续在场时间触发久坐提醒；隐私模式下出现第二人时，开发板以专用灯效告警并通过 USB 通知电脑显示不透明遮罩。用户可用 BOOT 键确认提醒、切换隐私及演示模式。摄像头画面不上传，事件以有界 JSONL 保存在开发板和电脑端，并可统计久坐、确认及隐私触发次数。系统针对摄像头、推理及电脑断连设计安全降级，实现了约 840 ms 单帧推理、0/1/2 人检测展示和板端—电脑端联动闭环。

## 3、正文

### 3.1 绪论

#### 项目背景与问题定义

长时间伏案会带来健康风险，而开放办公室、实验室或家庭书房中的屏幕内容又可能被身后来人看到。普通摄像头方案常依赖云端，既增加网络依赖与响应延迟，也引入图像上传风险。AgentGuard 面向长期使用电脑的学生、办公人员和内容创作者，将久坐提醒与多人隐私防窥合并为一个端侧闭环：板端只输出人数、边界框和结构化事件，不向电脑传输摄像头画面。

#### 技术难点

1. 在 ESP32-S3 有限内存和算力下同时完成 V4L2 取帧、ESP-DL 推理、LCD 实时预览及事件策略。
2. 保留 ESP-DL 官方算法层，只增加到 NuttX/openvela 的薄兼容层，并解决内存地址类别、量化算子、RGB565 字节序及模型输入问题。
3. 让 USB/HTTP、电脑通知或遮罩失败时不阻塞摄像头和板端告警。
4. 在单个 BOOT 键上提供提醒确认、隐私模式和 Demo 模式，同时避免误触发。

#### 创新点

- 技术层：以官方 ESP-DL 端侧模型为唯一人脸判断来源，图像不离开开发板。
- 场景层：将健康计时与“第二人出现”隐私策略组合为同一桌面终端。
- 交互层：LCD 人脸框、差异化 Power LED、BOOT 手势、电脑通知及全屏遮罩形成多模态反馈。
- 工程层：板端与电脑端均记录有界 JSONL，支持统计、复盘和故障安全降级。

### 3.2 系统方案设计

#### 系统总体架构

```text
摄像头 → V4L2/RGB565 → ESP-DL 人脸框与人数 → 健康/隐私状态机
                                               ├→ LCD 检测框与状态
BOOT 键 ────────────────────────────────────────┤→ Power LED 差异化灯效
                                               ├→ LittleFS JSONL
                                               └→ USB/HTTP → 电脑通知/遮罩 → JSONL 统计
```

数据流为：V4L2 获取 QVGA RGB565 帧；兼容层整理模型输入；ESP-DL 输出边界框和人数；确定性状态机根据人数、持续时间和模式生成去重事件；LCD、Power LED 和 LittleFS 提供本地反馈；USB/HTTP 只传输白名单结构化事件；电脑端显示通知或遮罩并统计事件。

#### 方案论证与选型

硬件选择 ESP32-S3-EYE，原因是其集成 OV2640、LCD、按键和 ESP32-S3 AI 指令能力，可在单板上形成完整演示。视觉框架选择 Espressif ESP-DL v3.2.0：相比云端视觉，它不上传图像且断网可用；相比早期颜色启发式，它能够真实检测人脸；相比在截止期内重新移植其他框架，保留官方模型和算法层的风险更低。

端/云职责明确划分：开发板负责图像采集、推理、健康/隐私决策、本地显示、灯效和事件保存；电脑只处理结构化事件、系统通知、全屏遮罩与统计。本作品没有云端视觉或云端模型。USB 是现场演示首选通道，免配网；HTTP 仅作为可选局域网入口，要求 Bearer Token 和事件白名单。断网、弱网或电脑断连时，板端推理、LCD、LED 和 LittleFS 继续运行，远端动作按尽力而为方式降级。

#### 关键模块设计

- `core.c`：无硬件依赖的久坐与隐私确定性状态机。
- `vision_espdl.cpp`：ESP-DL 到 NuttX/openvela 的薄兼容层。
- `agentguard_main.c`：相机、LCD、按键、LED、存储和通信适配。
- `storage.c`：有界 JSONL 保存、裁剪及板端统计。
- `monitor/`：电脑端事件校验、USB/HTTP 接收、动作派发、日志与统计面板。

### 3.3 核心算法与技术原理

#### AI 算法实现

系统采用 ESP-DL v3.2.0 `human_face_detect` 的 MSR+MNP 两阶段 S8 量化人脸检测模型，模型文件大小 191,248 字节，输入为 OV2640 QVGA 320×240 RGB565 图像。MSR 产生候选区域，MNP 进行二阶段确认并输出最终边界框；产品仅使用人脸框和人数，不进行身份或“主人”识别。当前同步推理单帧约 840 ms，约 1.19 FPS；完整固件的 text、data、bss 分别为 1,771,562、532,120、961,992 字节。项目未接入云端模型，也没有把图像发送给 MiMo 或其他在线服务。

适配尽量保持官方 detector wrapper、模型和阈值不变。兼容层负责 NuttX 内存接口、模型所需算子配置和相机 RGB565 字节序转换；最终以官方模型与硬件正对照定位并修复输入契约差异，而不是通过降低阈值制造检测结果。

#### 关键机制设计

无人时暂停久坐计时；单人持续在场时累计时间；达到阈值生成 `sedentary_alert`；短按 BOOT 生成 `acknowledged`；隐私模式中人数达到 2 时生成 `blur_screen`。模型输出经过 1.5 秒存在性保持，降低单帧漏检造成的界面抖动。隐私动作只在状态跃迁时触发，避免每帧重复通知。

通信采用非阻塞、尽力而为路径，电脑断连不会反向阻塞摄像头和本地告警。模型初始化、推理失败或持续超时时进入可见的 `AI ERROR` 安全状态，不用颜色启发式结果冒充 AI 检测，也不在错误状态下触发自动隐私动作。

#### openvela 系统能力的深度运用

作品落地了“图形 + AI + 多媒体”能力：使用 V4L2 和 OV2640 完成视频采集，使用 ESP-DL 完成人脸推理，使用 ST7789 LCD 完成 RGB565 预览、人脸框和 HUD；同时使用 NuttX 任务与同步、USB 串口、LittleFS 和 NSH 应用机制。项目增加了 ESP-DL 到 NuttX 的兼容层、Power LED 设备注册、LCD DMA 连续缓冲和摄像头 VSYNC 稳定性修复。

对 openvela 的改进建议：为 ESP32-S3 补充官方 ESP-DL 示例、量化算子配置模板及摄像头像素字节序说明；为 V4L2—ESP-DL—LCD 链路提供统一的零拷贝/缓存一致性接口；在板级配置中明确 LCD DMA 能力和 VSYNC 极性，减少 AI 视觉应用的重复适配成本。

### 3.4 系统实现

#### 软件 / 固件架构

固件按“硬件适配—AI 感知—确定性策略—反馈与存储”分层。开发先打通摄像头和 LCD，再用 ESP-DL 替换早期颜色启发式检测，随后加入多框映射、久坐计时、隐私状态、差异化灯效、LittleFS 留存和 USB 电脑代理。每次修改均通过主机单元测试、完整固件构建和实机观察逐层验证。

#### 数据流与关键流程设计

```text
取帧 → 推理是否成功？ ─否→ AI ERROR 安全状态并继续重试
  │是
  ↓
更新人脸框/人数 → 更新久坐与隐私状态 → 生成去重事件
  ↓                                      ↓
LCD + Power LED 本地反馈        LittleFS + USB/HTTP
                                         ↓
                              电脑通知/遮罩 + JSONL 统计
```

#### 硬件设计与适配

| 项目 | 内容 |

| 开发板/芯片 | ESP32-S3-EYE / ESP32-S3 |
| 板载器件 | OV2640 摄像头、ST7789 LCD、BOOT 键、GPIO3 绿色 Power LED |
| 外接模块 | 无；只需 USB 数据线和电脑 |

#### 应用 / 交互端设计

短按 BOOT 确认提醒；按住 3–7 秒后松开切换隐私模式；按住至少 8 秒后松开切换 Demo。Demo 将久坐阈值缩短到 20 秒。LCD 显示预览、人脸框、`FACE` 人数和 `SIT/P/D` 状态；久坐与隐私使用不同 Power LED 节奏。电脑端通过 `run_demo.py` 启动 USB 接收器和本地统计面板，并在隐私事件发生时显示全屏遮罩。MENU/UP 等电阻按键在当前板卡读数不可区分，因此没有作为最终入口。

#### 自定义 Skill

仓库沉淀了 `skills/develop-agentguard-openvela/`，用于 AgentGuard 构建、调试、烧录和验收，定义工作区定位、配置门禁、ESP-DL 兼容边界、分区安全、自动化测试和实机证据要求，满足比赛“至少 1 个 Skill”的提交要求。当前固件采用 ESP-DL 加确定性状态机，没有集成 LLM/`ai_agent`，因此该 Skill 是 AI Coding 开发期 Skill，不虚构为开发板 `/data/agent/skills/` 下的运行时 LLM Skill；运行时触发场景由编译进固件的健康与隐私状态机承担。

### 3.7 总结与展望

#### 成果总结

AgentGuard 已形成从 ESP-DL 端侧视觉感知、确定性健康/隐私策略、LCD 与 LED 本地反馈，到电脑通知、全屏遮罩和事件统计的可运行闭环。最终作品支持 `FACE:0/1/2`、多人框选、久坐提醒与确认、隐私模式、Demo 模式、LittleFS/电脑 JSONL 留存，并保留完整 README、自动化测试、AI Coding 日志和自定义 Skill。

#### 应用前景与商业价值

目标受众是约 16–60 岁、在办公室、实验室、宿舍或家庭书房长期使用电脑，并偏好本地隐私处理的学生、职员、研发人员和内容创作者。可采用“硬件终端销售 + 企业定制集成 + 开源基础版”的模式，不依赖持续云端订阅；结构化事件接口可以接入不同桌面系统、企业终端管理或智慧工位。算法层与策略层解耦，后续可迁移至更多 openvela 摄像头设备，并通过模型替换和量产外壳实现规模化。

#### 不足与未来工作

当前尚未完成标准数据集准确率、整机功耗、端到端通知延迟和两小时以上连续运行量化；双人边缘场景仍可能短暂回落为 1。后续将补充可复现实验集、功耗与长稳测试，优化模型性能和多人保持策略，完善外壳与安装方式，并评估资源允许时的本地 KWS。身份识别只有在用户明确授权、具备注册/撤销机制并完成隐私评估后才考虑加入。
