## 2. 作品摘要（300 字以内）

AgentGuard 是运行于 ESP32-S3-EYE 和 openvela/NuttX 的桌面健康与隐私守护终端。系统使用 ESP-DL 在设备本地检测并框选人脸，依据人数和持续在场时间触发久坐提醒；隐私模式下出现第二人时，开发板以专用灯效告警并通过 USB 通知电脑显示不透明遮罩。用户可用 BOOT 键确认提醒、切换隐私及演示模式。摄像头画面不上传，事件以有界 JSONL 保存在开发板和电脑端，并可统计久坐、确认及隐私触发次数。系统针对摄像头、推理及电脑断连设计安全降级，兼顾可演示性、隐私与可靠性。

## 3.1 项目背景、挑战与创新

长时间伏案会带来健康风险，而开放办公或居家环境中，屏幕内容又可能被身后来人看到。普通摄像头方案常依赖云端，既增加延迟，也引入图像上传风险。AgentGuard 将两类问题合并为一个端侧闭环：板端只输出人数、框和事件，不向电脑传输摄像头画面。

主要挑战包括：ESP32-S3 上有限内存与算力、ESP-DL 到 NuttX/openvela 的兼容、实时预览与推理共存、USB 断连不能拖死相机循环，以及物理按键在当前板卡上的可用性差异。创新点是将本地人数感知、久坐策略、自动隐私遮罩、双端审计日志和故障安全状态整合到一个小型终端中。

## 3.2 总体架构、选型与关键模块

硬件采用 ESP32-S3-EYE，使用板载摄像头、240×240 LCD、RGB 提示灯和 BOOT 键。操作系统为 openvela/NuttX，视觉推理采用 ESP-DL。电脑端采用仅依赖 Python 标准库的安全代理，以 USB 串口作为演示首选通道，HTTP 作为可选通道。

数据流为：V4L2 获取 RGB565 帧 → ESP-DL 检测并产生边界框 → 策略状态机根据人数、时间和模式生成事件 → LCD/RGB/LittleFS 本地反馈 → USB/HTTP 将允许的事件发送至电脑 → 桌面通知或隐私遮罩 → JSONL 留存与统计。

代码按层拆分：

- `core.c`：无硬件依赖的确定性策略状态机。
- `vision_espdl.cpp`：ESP-DL 到 NuttX/openvela 的薄兼容层。
- `agentguard_main.c`：相机、LCD、按键、LED、存储与通信适配。
- `storage.c`：有界 JSONL 保存、裁剪及板端统计。
- `monitor/`：电脑端事件校验、动作派发、日志与统计。

## 3.3 AI 算法、关键机制与 openvela 能力

系统使用 ESP-DL 人脸检测模型输出边界框及人数。项目尽量保留官方算法层，仅适配输入图像、内存和运行接口，以降低移植风险。检测结果不会用于身份识别，也不声称能识别“主人”。

策略层将 AI 输出转化为产品行为：无人暂停久坐计时；单人持续在场累计时间；达到阈值生成 `sedentary_alert`；用户短按 BOOT 生成 `acknowledged`；隐私模式中人数达到 2 时生成 `blur_screen`。事件通过白名单发送，通信使用尽力而为的非阻塞路径，电脑断线不阻塞推理。

openvela/NuttX 提供 V4L2 摄像头、LCD、任务/同步、串口、Flash 文件系统和 NSH 命令环境。板端事件保存在 LittleFS，电脑端代理负责系统通知与遮罩，形成端云无关的本地协同。

## 3.4 实现过程、软硬件与交互

开发首先完成摄像头和 LCD 通路，再以 ESP-DL 替换早期颜色启发式检测。随后加入多框映射、人数策略、久坐计时、隐私状态、差异化灯效、LittleFS 留存和 USB 电脑代理。每次功能修改通过主机单测、完整固件编译和实机观察逐层验证。

最终交互为：短按 BOOT 确认提醒；按住 3–7 秒后松开切换隐私；按住至少 8 秒后松开切换 Demo。Demo 将久坐阈值缩短至 20 秒，便于 5 分钟视频展示。MENU/UP 等电阻按键在当前硬件上读数不可区分，因此未作为最终入口。

摄像头帧只在开发板内处理。电脑只收到结构化事件，不收到图像。电脑代理限制事件类型；HTTP 模式要求 Bearer Token；锁屏属于显式可选能力，默认关闭。

仓库的 `skills/develop-agentguard-openvela/` 是开发阶段用于规范 AI Coding 的自定义 Skill。当前作品没有部署 `/data/agent/skills/` 下的 LLM 运行时 Skill，核心 AI 是 ESP-DL 板端推理。该项是否为本赛道强制交付物需向组委会确认，报告不作虚假声明。

## 3.7 总结、应用价值与未来计划

AgentGuard 已形成从端侧视觉感知、确定性策略、板端反馈到电脑联动和审计统计的可运行闭环。它适合开放办公室、家庭书房和需要本地隐私保护的工作台，且无需上传视频。

短期可补充长稳与功耗测试、优化两人边缘场景和完善成品外壳。后续可在不改变策略层的前提下替换更高效的 ESP-DL 模型，并在资源允许时增加本地 KWS；身份识别只应在用户明确授权、具备注册/撤销机制并完成隐私评估后考虑。
