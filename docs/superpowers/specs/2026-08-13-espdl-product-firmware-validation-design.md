# ESP-DL 产品固件恢复与真机验收设计

## 背景与结论

AgentGuard 已将 ESP-DL v3.2.0 的 MSR + MNP S8 人脸检测模型接入
ESP32-S3-EYE。2026-08-13 的真机 Saved PC 为 `0x421ba31f`，对应诊断镜像中
`espdl_hardware_acceptance_pass()` 的主动无限循环。该证据表明模型加载、两级
检测器构造和至少一次真实推理均已返回。

当前板上镜像和 `nuttx` ELF 仍是带验收循环的旧诊断构建，而工作区
`vision_espdl.cpp` 已恢复正常的持续推理实现。下一阶段不再扩展阶段标记，而是
从当前源码生成产品固件并完成真机回归。

## 目标和非目标

目标：

- 从当前源码做一次可追溯的干净增量重建，排除旧对象缓存。
- 确认最终 ELF 不含 `ag_acceptance_*` 和
  `espdl_hardware_acceptance_pass()` 诊断符号。
- 烧录产品固件并验证 AgentGuard 持续采集、LCD 刷新和 ESP-DL 检测。
- 确认 AgentGuard 进程持续存活，且已有 LittleFS、HUD 和策略状态机没有回归。
- 如出现故障，只围绕首次失败边界收集证据并做单变量修复。

非目标：

- 本轮不更换模型、不调整 0.60/0.60 阈值、不改变每三帧一次的推理节流。
- 不修改健康状态机、JSONL 格式、PC HTTP 协议或 Wi-Fi 配置。
- 不把现场观察等同于正式准确率测评；真实精度仍需单独数据集和指标设计。
- 不在本轮接入 ESP-SR、手势识别、动画或 HMAC/TLS。

## 架构与数据流

产品路径保持现有分层：

1. `agentguard_main.c` 从 `/dev/video0` 获取 320×240 RGB565 帧。
2. `vision.c` 在 `CONFIG_AGENTGUARD_ESP_DL=y` 时调用
   `ag_vision_model_process_rgb565()`。
3. `vision_espdl.cpp` 延迟构造 `HumanFaceDetect`，每三帧运行一次 MSR + MNP，
   其他帧复用最近一次结果。
4. 检测结果最多保留八张脸，并以面积最大的脸框驱动既有相对姿态分数。
5. `agentguard_main.c` 将人数和主脸框交给策略核心及 HUD；显示、日志和 PC 事件
   继续使用既有接口。

本轮不新增运行时诊断循环。构建后的符号检查是产品/诊断边界的强制门禁。

## 构建与烧录策略

先记录源码、配置与现有产物状态，再删除 AgentGuard 对应的旧构建对象或使用
构建系统支持的等价重建方式，使相关 C/C++/汇编文件全部重新编译。不得清理或
恢复 openvela 中与本项目无关的用户改动。

构建继续使用现有产品配置，包括：

- `CONFIG_AGENTGUARD_ESP_DL=y`
- `CONFIG_XTENSA_CP_INITSET=0x0009`
- 单核配置及既有 BLE 隔离
- LittleFS 分区起点 `0x300000`

生成镜像后检查：编译确实覆盖 ESP-DL 适配文件；ELF 含正式入口；ELF 不含验收
循环；`nuttx.bin` 小于 `0x300000`；镜像信息和校验有效。满足门禁后才烧录，烧录
必须完成写后哈希验证。

## 真机验收

实体 RESET 后依次验证：

1. NSH 正常出现，启动期间无 CP3、Bluetooth HCI 或 `hpwork` 异常。
2. `agentguard` 启动，OV2640 和 LCD 初始化成功。
3. LCD 画面持续活动，HUD 持续刷新，而非停在验收帧或静止画面。
4. 无人、单人和多人条件下 `FACE:n` 至少具有方向正确的变化；重点确认单人不再
   被旧肤色启发式稳定误报为多人。
5. 主脸框随人脸位置移动；`pidof agentguard` 在持续运行后仍返回相同 PID。
6. `agentguard stats` 可读取既有 LittleFS 日志，已有数据不被固件烧录覆盖。

若 USB 串口打开导致软件复位，则使用项目已有的硬件串口探针和实体 RESET 流程，
并明确区分“软件复位日志”和“实体复位运行证据”。

## 错误处理与调试规则

- 构建失败：先定位首个编译或链接错误，不叠加不相关兼容改动。
- 符号门禁失败：视为旧对象仍被链接，先追踪对象来源，不烧录。
- 启动异常：保存完整异常原因和 PC，使用同一 ELF 符号化后再提出修复。
- 推理或刷新停滞：先确定停在构造、预处理、MSR、MNP、后处理还是显示边界；
  每轮只验证一个假设。
- 现场检测效果不佳但循环稳定：记录为模型阈值/输入处理的后续测评问题，不在本轮
  临时调参掩盖。

## 验证范围与完成标准

软件回归包括主机 C 测试、PC 代理单元测试、工作区 Skill 校验、openvela 交叉
构建和 ELF/镜像检查。真机回归包括启动、持续刷新、检测变化、进程存活和
LittleFS 非破坏性检查。

只有以下条件同时满足才算本阶段完成：产品 ELF 已移除诊断循环；固件成功烧录；
实体 RESET 后 AgentGuard 持续运行；LCD 与检测结果持续更新；已有核心测试无回归。
准确率、性能基准和比赛完整网络演示仍作为独立后续任务记录。
