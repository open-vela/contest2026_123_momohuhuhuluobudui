# ESP-DL 实时人脸权威链恢复设计

**日期：** 2026-08-21

**状态：** 待用户审阅

## 背景与已知事实

AgentGuard 当前同时运行 ESP-DL MSR+MNP S8 人脸检测和肤色连通块回退。真机已经
得到以下可重复证据：

- TIE 卷积自检为 `K:11`，内置 320x240 RGB565 参考图可得到 `F:1`；模型加载、
  两级检测器构造和至少一条有效推理路径成立。
- 实时摄像头帧在真人与无人场景下都固定为约 `S:57 M:1 F:0`：MSR 总是产生一个
  与真人无关的候选，MNP 总是拒绝它。
- 将实时帧旋转 180°没有改变结果；RGB565 的四种 swap/big-endian caps 组合也都
  得到相同结果。方向和 caps 枚举已经按退出条件终止。
- 摄像头预览颜色、方向和完整画面可见。ESP32-S3 CAM 下半层在 DMA 完成后失效
  cache，再通过 CPU `memcpy` 填充 V4L2 用户缓冲；不能在没有新证据时继续盲加
  cache 操作。
- 便携 C 普通卷积和深度卷积使参考信号从错误的 TIE 数值恢复，但实时推理约需
  840 ms。性能问题与本设计的正确性问题分离。
- 肤色回退可在真人居中时产生框，但也会把手掌或肤色背景判为脸。1.5 秒迟滞会被
  这些新误检续期，使人离开后的错误 `FACE:1` 持续约 2–3 秒。

因此，肤色连通块不能继续作为产品的权威人脸检测器。下一阶段恢复 ESP-DL 作为唯一
权威来源，并用同帧证据定位实时帧从 V4L2 到 MSR/MNP 的第一处分歧。

## 目标

1. 证明同一个实时帧在原始 RGB565、MSR 预处理输入、MSR 输出、MNP 裁剪输入和
   MNP 输出各边界是否随场景变化。
2. 将故障定位到第一个不满足预期的边界，每轮只修复该边界，不同时改变阈值、方向、
   caps、后端或 LCD 链路。
3. ESP-DL 通过真人、无人和手掌验收后，使策略核心、HUD 人数和人脸框只消费
   ESP-DL 结果。
4. 将肤色回退降级为明确标记的诊断数据，不得再直接生成产品 `FACE` 或给迟滞续期。

## 非目标

- 不处理 LCD 扫描线、SPI/DMA 时序或摄像头预览刷新率。
- 在证据指向阈值之前，不调整 MSR/MNP 0.50 分数阈值。
- 不再次枚举图像方向或 RGB565 caps。
- 不更换模型，也不把人脸识别、身份识别或手势识别加入本阶段。
- 不修改或 push openvela 官方源码。若证据最终指向官方 CAM/V4L2/缓存边界，应先
  在交接文档记录所需补丁，并等待用户批准及官方检查后另行实施。

## 总体架构

诊断数据流保持单向：

```text
V4L2 RGB565 frame
  -> raw-frame fingerprint
  -> ESP-DL MSR preprocess fingerprint
  -> MSR output fingerprint + candidates
  -> each MNP crop fingerprint + MNP score
  -> raw ESP-DL result
  -> product authority gate
  -> policy core / HUD / face box
```

所有指纹必须来自同一次完整推理并携带同一个推理序号。诊断只读取已有缓冲，不修改
像素，不改变 V4L2 的 QBUF 时点，也不在显示线程访问摄像头缓冲。参考图与实时图使用
同一套指纹算法，避免比较两套实现生成的不可比数据。

### 指纹内容

原始帧记录：

- 整帧确定性 32 位哈希；
- 上、中、下三个区域的独立哈希；
- RGB565 采样的最小值、最大值和非零采样数量。

预处理张量和模型输出记录：

- 张量数据类型、元素数量、最小值、最大值和 32 位哈希；
- MSR `score0`、`score1` 及框输出的哈希和最高概率；
- MSR 候选数量及最大候选框；
- 每个 MNP 候选的裁剪框、预处理张量哈希、最高概率和最终接受数量。

哈希用于判断数据是否变化和两个副本是否一致，不作为密码学或图像相等性承诺。
实现必须逐字节处理，结果不得依赖结构体填充、指针地址或主机字节序。

## 分阶段诊断与退出条件

下一份实施计划只覆盖阶段 A。阶段 B 的修改对象取决于阶段 A 的真机证据，阶段 C
又取决于阶段 B 的验收结果；二者必须分别形成后续设计/计划并重新获得用户批准，不能
在同一轮实现中预先猜测。

### 阶段 A：定位第一处静止边界

在内置参考图、无人实时场景、真人居中实时场景和手掌场景分别采集完整诊断。LCD
只显示一页可人工抄录的紧凑阶段码；完整数值保存在应用自己的只读诊断快照中，可由
现有命令入口输出。不得把每帧日志写入 LittleFS，也不得在推理热路径持续打印。

解释规则：

- 原始帧区域哈希不随明显场景变化：故障在 V4L2 用户缓冲内容、缓冲所有权或采集
  完整性，停止检查 ESP-DL。
- 原始帧变化而 MSR 输入哈希固定：故障在图像预处理读取、地址类别、缓存可见性或
  caps 传播；先比较原缓冲与推理前稳定副本。
- MSR 输入变化而 MSR 输出固定：故障在模型数值执行、张量复用或算子后端；从 MSR
  第一层开始做参考/实时张量检查，不改后处理阈值。
- MSR 输出和候选随真人变化，但 MNP 裁剪输入错误或固定：故障在候选框变换或 MNP
  ROI 预处理。
- MNP 输入变化合理但输出固定拒绝：故障在 MNP 数值路径或后处理；只对 MNP 做
  层级隔离。

阶段 A 只收集证据，不包含行为修复。取得一个明确的第一处分歧后停止并记录，不把
多个假设合并进下一固件。

### 阶段 B：单边界修复

为阶段 A 确认的边界编写最小复现测试，再实施一个变量的修复。优先在 AgentGuard
应用或 ESP-DL 兼容层解决；只有应用层证据证明官方驱动边界错误时，才提出独立的
openvela 官方源码补丁供官方检查。

修复后的同帧诊断必须证明第一处分歧已消失，并且后续边界获得新的、可解释的输入。
若修复没有改变目标指纹，立即回退该实验并返回阶段 A，不叠加第二个猜测。

### 阶段 C：恢复权威结果

诊断期间，当前提交 `8a99d6c` 保持为可烧录回退点。ESP-DL 未通过验收前，不得把
肤色结果描述为真实人脸结果。

ESP-DL 通过验收后：

- `ag_vision_model_process_rgb565()` 的结果成为 `observation.face_count`、HUD
  `FACE` 和主框的唯一来源。
- `ag_face_fallback_apply_rgb565()` 可保留在诊断构建中输出单独的 `SKIN` 指标，
  但默认产品配置不调用它，也不能写入 `ag_vision_result`。
- 现有 `ag_face_presence_filter()` 不参与首次 ESP-DL 验收，以免掩盖原始漏检或延长
  离场状态。只有原始神经网络结果证明存在孤立单帧漏检后，才另行设计一个只由
  ESP-DL 真阳性续期的短迟滞。
- P0–P3 caps 循环在诊断结束后恢复为官方默认的固定 caps，避免长期产品固件继续
  轮换已排除的模式。

## 显示与诊断接口

240x240 LCD 不能承载全部指纹。屏幕只显示：诊断阶段、推理序号、原始帧是否变化、
MSR 输入是否变化、MSR/MNP 候选数和最终 ESP-DL 人脸数。完整快照由
`agentguard face-diag` 命令按固定字段顺序输出一次；命令只读取最近一次完成快照，
不启动推理、不打开摄像头、不改变检测状态。

诊断快照在发布时整体复制并带有效位。读者永远不能看到一半属于上一推理、一半属于
下一推理的数据。无快照、张量不存在、元素数量溢出或模型返回错误时，对应字段明确
标记无效，不以零冒充有效测量。

## 错误处理与安全边界

- 指纹计算使用有界元素数量；空指针、零尺寸和不支持的数据类型返回无效状态。
- 诊断不得分配整帧长期内部 RAM，也不得改变 ESP-DL 内存规划。
- 若需要稳定副本，必须证明原缓冲和副本哈希一致，并确保复制发生在 DQBUF 后、
  QBUF 前；分配失败时保留原路径并报告诊断无效。
- 不在每帧路径写文件或串口，避免诊断本身改变约 840 ms 推理时序。
- 摄像头重启会清除诊断有效位和推理序号关联，禁止跨流比较。
- 所有实验提交、烧录镜像哈希和真机结果写入 `AGENTGUARD_PROGRESS.md`。

## 测试策略

实施遵循测试驱动开发：

1. 纯 C/C++ 指纹测试使用手工给定字节序列和固定期望哈希，证明内容变化、区域变化、
   空输入和长度边界行为。
2. 诊断快照测试证明一次发布是完整同代数据、无效字段不会显示为有效、读取不会改变
   状态。
3. UI/命令格式测试使用固定结构体输入验证紧凑阶段码和完整字段顺序，不 grep 源码。
4. 权威门测试证明肤色候选不能改变产品 `face_count`，只有 ESP-DL 结果能生成框；
   诊断开关也不能改变该契约。
5. 现有 AgentGuard 主机测试、工作区检查和 NuttX 目标构建全部通过；每次烧录必须
   得到 esptool 的 `Hash of data verified`。

阶段 A 的真机测量本身不是可由主机测试替代的结果。每个场景至少保持四次完整推理，
记录原始帧、预处理和两级输出是否随场景一致变化。

## 产品验收标准

恢复 ESP-DL 权威链必须同时满足：

- 真人居中连续 30 秒：原始 ESP-DL 输出至少 75% 的完整推理为 `FACE:1`，框位于
  脸部并随脸移动；不得依赖肤色回退或迟滞制造该结果。
- 无人连续 30 秒：持续 `NO PERSON`，无框。
- 单独伸入手掌连续 30 秒：持续 `NO PERSON`，无框。
- 真人离开：不使用迟滞的原始 ESP-DL 结果在下一次完整推理后恢复 `NO PERSON`。
- 内置参考图继续为 `F:1`，`K:11` 不回归，进程持续运行。
- 显示方向、文字可读性、完整画面和无彩色横条保持现状；扫描线与低刷新率明确留给
  后续独立性能阶段。

在上述条件全部满足前，不宣称真实人脸检测已经修复，也不删除提交 `8a99d6c` 的可
追溯回退能力。
