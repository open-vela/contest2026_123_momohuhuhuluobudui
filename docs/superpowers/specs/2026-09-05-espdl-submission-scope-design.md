# AgentGuard ESP-DL 截止期收敛设计

## 背景与结论

比赛提交截止时间为 2026 年 9 月 20 日。AgentGuard 已具备摄像头预览、
LCD 状态界面、久坐与坐姿状态机、隐私事件、PC 代理和本地行为日志，但正式
人脸输入仍未达到可验收状态。

肤色连通域只能作为早期摄像头联调工具，不能作为正式人脸检测依据。正式产品
必须以 ESP-DL 为唯一人脸判断来源。当前 ESP-DL MSR+MNP 链路已修复 release
构建中预处理表达式被消除的问题，但最新全 C 固件在空场景仍输出五个结果；同一
固件的真人对照尚未采集。因此，截止期内不承诺身份识别或任意人数精确计数，而是
收敛到可直接支撑 AgentGuard 决策的三态输出：`0`、`1` 和 `2+`。

正式验收目标是：无人时不报人脸，单人时稳定框出主脸，两人及以上时进入多人
状态。主人在本设计中仅指画面中的主要使用者，不表示身份注册或身份比对。

## 目标与非目标

### 目标

- ESP-DL 是生产数据流中唯一的人脸检测来源。
- 对外只输出 `0`、`1`、`2+` 三种人数状态。
- 单人状态输出一个稳定主脸框，供 LCD、久坐和坐姿逻辑使用。
- 多人状态驱动现有隐私围栏事件。
- 对模型初始化、推理失败和持续超时提供安全降级，避免误触发自动动作。
- 使 Git 中的比赛源码、模型、许可证、PC 代理、Skill 和复现说明完整，确保评审
  通过干净 clone 能执行测试和构建。
- 产生可写入技术报告和演示视频的量化真机证据。

### 非目标

- 不识别具体人物身份，不保存人脸特征模板。
- 不承诺三人及以上的精确人数，只保留 `2+`。
- 不开发语音 KWS、手势调光或新的 LCD 动画。
- 不继续修改 LCD/NuttX 底层传输架构。
- 不以无限期逐算子排查作为当前主线。
- 不使用肤色检测结果填补 ESP-DL 失败。

## 方案选择

### 选择：限时验证现有链路，失败后切换官方模型

先完成当前全 C 固件的真人对照。若 ESP-DL 的真人与空场景结果在候选坐标、分数
或稳定性上存在可利用差异，则在现有输出之上实现候选过滤、去重和时间稳定；若
没有差异，则停止继续调阈值和深挖 portable C 算子，转为替换另一套可验证的官方
ESP-DL 人脸模型或与其匹配的 ESP-DL 版本。

现有模型证据采集最多占用半天；模型/版本替换最多占用两天。到达退出条件后必须
重新评估范围，不允许无期限延长底层诊断。

### 未选择：直接替换模型

直接替换可能绕过当前数值问题，但会同时引入模型格式、内存、工具链和 NuttX
兼容风险。现有全 C 固件只差真人对照，先完成这个门槛成本更低。

### 未选择：继续逐算子追查

该方案最有机会得到完整根因，但时间不可预测，且不能直接保证提交前形成稳定
演示，不作为当前主线。

## 架构与数据流

```text
V4L2 RGB565 帧
  -> ESP-DL MSR+MNP 推理
  -> 候选合法性与置信度过滤
  -> 重叠候选合并和去重
  -> 时间稳定器
  -> 0 / 1 / 2+ 人数状态 + 主脸框
  -> AgentGuard 决策核心
  -> LCD、LED、JSONL 和经鉴权的 PC 事件
```

现有 `vision_espdl.cpp` 继续负责 ESP-DL 生命周期和原始结果适配。新增或抽取的
纯逻辑后处理模块接收候选框、置信度和时间序列，不访问摄像头、LCD、文件或网络，
以便在主机上确定性测试。

候选处理顺序固定为：

1. 拒绝坐标非法、裁剪后无面积或尺寸比例明显异常的框。
2. 应用经真机数据确定的置信度门槛；门槛不得只根据单个场景拍脑袋设定。
3. 对高度重叠候选执行去重，避免同一张脸被重复计数。
4. 按面积和置信度选择主脸框。
5. 将有效候选数折叠为 `0`、`1`、`2+`。
6. 通过连续推理确认和有限时间保持，减少状态与框闪烁。

主循环必须移除 `ag_face_fallback_apply_rgb565()` 对生产结果的补写。肤色模块可
暂时保留以便审计历史，但不得参与人数、主脸框、隐私或健康决策。

## 状态稳定与决策语义

- 从 `0` 进入 `1` 或 `2+` 需要连续多次有效推理确认。
- 从 `1` 进入 `2+` 同样需要连续确认，避免单帧重复框误触发隐私围栏。
- 短暂漏检可在有限窗口内保留上一次稳定状态和主脸框；超过窗口必须回到 `0`。
- 单人状态使用最大且稳定的候选作为主脸，不代表身份识别。
- 多人状态只要求确认至少两个互不重叠的稳定候选，不承诺更大的精确数量。
- 稳定器的确认次数和保持时间由录制的真机序列确定，并作为配置常量和测试用例
  固化，不能仅通过主观观感调整。

## 故障与安全降级

ESP-DL 初始化失败、推理返回错误或连续超过允许时限时，系统进入明确的
`AI ERROR` 状态：

- LCD 显示模型不可用，不显示肤色框或伪造人数。
- 暂停依赖人数的久坐累计、姿态提醒和自动隐私切换。
- 保留摄像头预览、按键、日志查询和故障记录能力。
- 不因未知人数自动锁屏。
- 模型恢复后重新经过连续帧确认，不直接继承错误前的稳定人数。

一次普通的 `0` 检测不是模型错误；只有显式返回失败或连续超时才进入
`AI ERROR`。这样可以区分“画面无人”和“系统不知道是否有人”。

## 显示与演示界面

产品界面保留摄像头画面、主脸框、人数三态、久坐时间、隐私状态和提醒状态。
Stage A/B 使用的哈希、缩放系数、MNP 计数等深度诊断信息不作为最终默认 HUD，
仅在显式诊断构建中保留。产品 HUD 至少显示：

- `FACE:0`、`FACE:1` 或 `FACE:2+`；
- 单人状态下的主脸框；
- 推理耗时或 `AI ERROR`；
- 现有健康、隐私和确认提示。

## 提交完整性

代码实现前先修复比赛仓库的可复现性。当前 HEAD 未跟踪若干构建必需内容，包括
便携核心、视觉和存储源码、Kconfig、PC 代理、项目 Skill、模型文件以及部分
ESP-DL 依赖。整理时必须：

- 将构建和运行必需的源码、头文件、模型、许可证、脚本与文档纳入 Git。
- 使用 `.gitignore` 排除对象文件、测试二进制、缓存和其他生成物。
- 不提交 Wi-Fi 密码、共享令牌、个人地址、固件镜像或临时 JTAG 转储。
- 不删除或恢复与本任务无关的既有用户修改。
- 在独立临时目录验证干净 clone，而不是只验证已有工作树。

## 测试与验收

### 主机测试

- 候选坐标裁剪、无面积框拒绝和尺寸过滤。
- 重叠框去重、两个独立框保留和 `2+` 折叠。
- 主脸选择规则。
- `0 -> 1 -> 2+ -> 1 -> 0` 的确认与保持序列。
- 时钟回退、推理错误和超时后的 `AI ERROR` 行为。
- 模型错误状态不得触发隐私、久坐或锁屏动作。
- 原有便携核心、存储、显示和 PC 代理回归测试。

### 干净副本验证

- 工作区契约检查通过。
- 从当前提交创建的独立副本能够运行 AgentGuard 主机测试和 PC 代理测试。
- 官方 ESP32-S3-EYE 配置能够完成 openvela/NuttX 目标构建。
- 固件镜像低于 LittleFS `0x300000` 分区边界。

### 真机最低验收

- 空场景连续 2 分钟不出现人脸框。
- 单人在不同距离和位置测试 10 次，至少 8 次能稳定框出主脸。
- 两人进入画面测试 5 次，至少 4 次进入 `2+`。
- 记录推理延迟中位数和最大值。
- 连续运行至少 30 分钟，无崩溃、白屏或相机失联。
- 所有未达到的指标如实记录，不以编译或主机测试替代真机检测结论。

## 实施顺序与退出条件

1. 整理 Git 跟踪边界和 `.gitignore`，建立干净副本测试基线。
2. 采集当前全 C 固件真人数据并与已有空场景快照比较。
3. 若存在可利用差异，以 TDD 实现候选后处理和三态稳定器。
4. 若不存在差异，在两天时限内切换官方 ESP-DL 模型/匹配版本并重新通过第 2 步。
5. 接入决策核心和精简产品 HUD，执行完整主机测试、交叉构建与真机验收。
6. 使用实际数据完成技术报告测试表、限制说明和五分钟演示脚本。

在单人检测通过前，不实现精确多人计数、身份识别、语音、手势或新的 LCD 优化。

## 完成标准

以下条件全部满足才可称为截止期内的正式版本：

- 生产数据流只使用 ESP-DL 人脸结果。
- 真机能稳定区分无人和单人，并在单人时显示主脸框。
- 真机达到约定的 `2+` 最低测试结果，或在提交材料中明确标为未达成而不伪报。
- 模型失败时进入安全且可见的错误状态。
- 干净 clone 能运行测试并完成官方 BSP 构建。
- 技术报告和演示材料中的性能、准确性及限制均有对应证据。
